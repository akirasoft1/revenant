## `sc_location_shops`

**`sc_location_shops(location, category=None, exclusive_only=False, limit=40)` (added 2026-09-28):** answers "what's sold at Levski" / "what's unique to Levski for purchasing" — the gap the 2026-09-28 hallucination incident (root `CLAUDE.md` "Star Citizen Knowledge") fell into. Built from UEX `items_prices_all` (~24k price rows) + `terminals` + `categories`, no Wiki call. **Location resolution is exact-field-match-first, then token-match, most-specific tier first** (city/station/outpost → moon/planet/orbit → system → terminal name/nickname), so "Nyx" resolves to the star *system* rather than sweeping in the unrelated "Nyx Gateway" stations that merely token-match at the station tier, and "Levski" (a city) never pulls in the rest of Nyx. Only terminals with `is_available_live == 1` count for both resolution and exclusivity — UEX still carries dead rows like the pre-Nyx "Dumper's Depot - Levski". **Exclusive** means no other *live* UEX-reporting terminal has a buy price for that item — exclusivity is relative to player-reported UEX data, not ground truth, and the response says so. `category` accepts a raw section/category name or the `"ship parts"`/`"ship components"` and `"fps gear"`/`"fps equipment"` aliases (joinable with "or"); an unrecognised category is ignored with a note, never a failure. A broad query (e.g. a whole system) is capped: items are selected **round-robin across sections** (never section-sorted truncation, which starved a Levski "ship parts or fps" query down to just Armor and Clothing) up to `limit` (clamp 1–100), with `section_counts` carrying the untruncated per-section totals so the model can say what else exists there. **Latency:** all three datasets are prefetched at server startup (`warm()`) and cached with a 3600s TTL; past expiry a call is served the stale value immediately while a single-flight background refresh runs, so a cold post-restart call never pays the ~6 MB `items_prices_all` refetch inside the voice path's 6s tool bound.

## Caching

**Cache TTLs + stale-on-error:** trade routes / commodity prices 1800s, item/vehicle prices 7200s, stats/missions/factions 43200s, name index/vehicles/terminals 21600s — chosen per how fast each upstream actually changes (prices drift hourly, stat blocks only move on a patch). On an upstream failure, a cached-but-expired value is still returned with `stale: true` + `age_minutes` rather than surfacing an error, because a slightly-stale trade route beats no answer in a voice conversation. (Exception: `sc_location_shops` also serves its expired price copy while a background refresh runs, so the first call after each hourly expiry reports `stale: true` with `age_minutes` ≈60 even when UEX is healthy.) Every result also carries `source` and `game_version` (except `sc_location_shops`, whose UEX price rows have no game version — it reports `latest_report` instead, so `note_patch` never fires for it) so a stale or off-patch answer is visible to the caller, not silently wrong.

## Server: `/mcp` and `/healthz`

**`/mcp` Host allow-list — or every in-cluster call is `421`:** mcp 2.2's `streamable_http_app` defaults `host="127.0.0.1"`, which silently enables DNS-rebinding protection with a loopback-only Host allow-list, so every in-cluster request (Host `sc-knowledge.discord-article-bot.svc.cluster.local:8080`) was rejected `421 Invalid Host header` while `/healthz` (a custom route, not guarded) stayed green. `server.py` passes explicit `TransportSecuritySettings` (protection ON) with `SC_ALLOWED_HOSTS` (comma-separated, `name:*` = any port; defaults to every in-cluster spelling of the Service plus loopback). A renamed Service or a new caller hostname must be added there. A 421 is a server-config problem, not the NetworkPolicy — the voice sidecar's startup warning prints the actual exception class/message for exactly that reason.

**`/healthz` never touches upstream:** it reports the CACHED live game version (`TTLCache.peek`, `null` when cold) and, if missing/expired, starts ONE single-flight background refresh. It used to await the UEX fetch (3 attempts × 8s read) — a UEX outage blew the kubelet's 1s probe timeout and restart-looped the pod; the tracked probes now also set `timeoutSeconds: 2`. The per-tool-call `note_patch` lookup is likewise bounded at 0.5s (under `asyncio.shield`, so the wait is abandoned, not the fetch) so a Wiki-only answer never waits on UEX and the voice 6s bound holds. `TTLCache` additionally backs off a failed key for 30s — during the window it serves the stale entry (or re-raises) immediately instead of paying the retry budget again.

## Result quality

**Rank/mission outlier flagging:** `sc_faction_missions` ranks by rep-per-minute, but a single anomalous record (e.g. one very-high-rep mission that isn't representative of the grind) can otherwise dominate the ranking and mislead a player. Missions more than 3× the median rep/min are kept in the results but flagged with a caveat rather than dropped — visible-but-distrusted beats silently-hidden or silently-trusted.

**Vehicle ambiguity — token filter, not fuzzy-match-everything:** `sc_find_item` only surfaces a ship/vehicle as an ambiguity candidate when it shares a *whole token* with the query (not a fuzzy/substring match), and otherwise returns an honest `not_found` rather than guessing. Loose fuzzy matching on vehicle names pulled in unrelated noise (e.g. a query for one ship fuzzy-matching a completely different one that merely shares a few letters); an honest "not found" is more useful than a wrong guess in a voice conversation where the user can't see a disambiguation list.
