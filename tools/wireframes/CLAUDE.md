# tools/wireframes — development notes

Moved verbatim from the root `CLAUDE.md` on 2026-10-12 to keep that file small. Claude Code loads this file when it works in `tools/wireframes/`. Usage is in `README.md` here; spec: `docs/superpowers/specs/2026-10-11-ship-wireframes-design.md`.

**Read the HARD RULE in the root `CLAUDE.md` "Member hangar" first: extracted game data (`.glb`, `.swf.gz`, anything derived) never enters the repo or an image, and tests build all geometry in code (`tests/synth.py`).**

Related notes: `hangar-editor/CLAUDE.md` (the viewer, including level of detail and hidden-line removal, which depend on this pipeline's longest-first line order and `views` mask), `hangar-service/CLAUDE.md` (storage, upload validation in `swf.py`, slot matching, known limits).

- **Pipeline — `tools/wireframes/` (README there), pure Python ≥ 3.11 + numpy, no Blender, no GPU.** Run from `tools/`: `python -m wireframes build <file.glb>`, `build-all <folder> --jobs N`, `inspect <bundle>`. **StarBreaker export settings:** GLB, LOD 1, Texture Mip 6 (textures unused; keeps the file small), interiors excluded, no lights, no animations. The GLB is Y-up under a `CryEngine_Z_up` root with every game hardpoint as a named node; the class name is a node's `extras.entity_name` (`EntityClassDefinition.<ClassName>`, same name as the Wiki catalog), or `--class-name` (required when the GLB has none). **Steps (defaults):** weld vertices on a 1 mm grid → keep boundary edges and creases sharper than `--crease-deg 60` → place with node world transforms → measure the ship once as the **robust extent** (bounds of edges within 1.25× the 99.5th-percentile distance from the median midpoint; the build warns when it is >10% smaller than the raw box, because a detached decal tens of metres off the nose must not inflate the size and thin the wireframe) → **outside-visibility cull** (surfaces point-sampled into depth maps from 26 directions, `--depth-res 640`; an edge survives if any of 3 points along it is at the front of some view within 2 pixels; without it the Ironclad was an unreadable block; `--no-visibility` skips it) → drop edges shorter than `--min-edge-frac 0.0025` × the robust longest dimension → **stray filter** (midpoint farther than 1.25× the robust radius) → **line budget** `--max-lines 60000`, longest first (the server refuses >80,000) → quantise to int16 → gzip. Sampling is seeded, so a build is byte-reproducible. **`--jobs` (build-all) defaults to 8** (the owner's P-core count, never "all cores") and each worker is a fresh process that sets `OMP_NUM_THREADS`/`OPENBLAS_NUM_THREADS`/`MKL_NUM_THREADS=1` before numpy loads, so `--jobs 8` really is 8 cores; `cli.py` and the package `__init__` must stay free of top-level numpy imports for that to hold (a test checks it). A failing ship doesn't stop the others; exit non-zero if any failed or two files yield one class name. Measured (tools/wireframes/README.md and spec spike): ~1–5 s per ship on one core, ~200–700 MB memory (the 120 MB / 3.9M-triangle Ironclad Assault ≈ 5 s); bundles typically 100–650 KB — Avenger Stalker 15k lines / 123 KB, Harbinger 26k / 227 KB, 890 Jump 28k / 251 KB, Ironclad Assault 60k (capped) / 510 KB.
- **Bundle format `.swf.gz`:** gzip of `b"SWF1"` + `uint32 LE headerLen` + header JSON + `int16 LE × lines×6`; coordinate = `center + int16/32767 × halfExtent`, metres, glTF Y-up (`space: "gltf-y-up-m"`). Header: `format` (1), `kind`, `className`, `sourceName`, `space`, `center`, `halfExtent`, `lines`, `nodes` (`[{name, parent: idx|-1, pos}]` — every named node that is a hardpoint (name starts with `hardpoint`, any case) or has a hardpoint ancestor/descendant, capped at 5,000), `build`.
