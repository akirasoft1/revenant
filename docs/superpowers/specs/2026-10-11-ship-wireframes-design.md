# Hangar: rotatable ship wireframes with real hardpoints — Design

**Date:** 2026-10-11 · **Status:** approved (chat) · **Branch:** `feat/ship-wireframes`
Supersedes Terminal-view follow-ups 1–3 (hand placement tool, extracted-position importer, 3D view).

## Goal
The Terminal view's ship panel shows a rotatable, consistently styled **wireframe** of the ship with glowing markers at the real hardpoint positions (the owner's end-state aesthetic). Wireframes are produced on the owner's machine from StarBreaker `.glb` exports and uploaded through an admin page.

## Spike results this design rests on (2026-10-11)
- StarBreaker `.glb` (settings: **LOD 1, Texture Mip 6, interiors excluded, no lights/animations**) is plain glTF 2.0 (no Draco), Y-up under a `CryEngine_Z_up` root, with every game hardpoint as a named node and the hierarchy intact; a root node's `extras.entity_name` is `EntityClassDefinition.<ClassName>` (e.g. `AEGS_Vanguard_Harbinger`) — the same class name the Wiki catalog uses.
- Pure Python + numpy pipeline (no Blender): weld vertices at 1 mm → keep boundary edges and creases > 60° → keep only edges visible from outside (surface point-splat depth maps from 26 directions, 3 test points per edge) → drop edges shorter than 0.25% of the longest dimension → cap at 60,000 longest edges. Results with the outside-visibility step (pipeline as built): Avenger Stalker 15k lines / 123 KB; Harbinger 26k / 227 KB; 890 Jump 28k / 251 KB; Ironclad Assault 60k (capped) / 510 KB (the spike's 19k / ~52k figures for the Stalker and 890 Jump were measured before visibility culling). Without the outside-visibility step the Ironclad was an unreadable block.
- Slot ids resolve by walking the node tree by name per path segment (sub-ports like `turret_left` do not start with `hardpoint`): Stalker 15/15, Harbinger 12/12, Ironclad 31/33 (2 ambiguous: duplicate `hardpoint_quantum_drive`/`hardpoint_radar` nodes), 890 Jump 19/26 (7 Wiki PDC ports absent from the model).

## Hard constraint — extracted data never enters the repo or an image
This repo and its history are public. Bundles, GLBs and any extracted geometry live only on the owner's machine and in private storage served to signed-in members (same posture as `OrgGuides/`). Tests use synthetic geometry generated in the test. `.gitignore` gains `*.swf.gz`, `*.glb`, `tools/wireframes/out/`.

## Decisions (owner-approved)
- **Delivery:** the script writes one bundle per ship; an **admin-only "Ship models" page** uploads/lists/previews/deletes them. No credentials on the desktop beyond the normal Discord login.
- **Display:** when a ship has a wireframe the panel shows it **by default**, with a small `Wireframe | Render` switch remembered per browser (`localStorage` `hangar.shipVisual`, try/catch → wireframe). Ships without one show today's render panel unchanged.
- **Generic by kind:** format, storage and viewer are keyed by `kind` + class name (`vehicle` now) so item/weapon wireframes can reuse them later (owner's planned next spike). Only `vehicle` is built.
- **Parallelism is explicit:** `build-all --jobs N` (default 8 — the owner's P-core count; never "all cores"), and each worker pins numpy/BLAS to 1 thread (`OMP_NUM_THREADS`/`OPENBLAS_NUM_THREADS`/`MKL_NUM_THREADS=1` set before numpy import) so `--jobs` is the real core count. No GPU.

## 1. Pipeline — `tools/wireframes/` (Python ≥ 3.11, numpy only)
CLI (`python -m wireframes …`, run from `tools/`):
- `build <file.glb> [-o OUT_DIR] [--crease-deg 60] [--min-edge-frac 0.0025] [--max-lines 60000] [--no-visibility] [--depth-res 640] [--kind vehicle] [--class-name NAME]` → `OUT_DIR/<ClassName>.swf.gz`, prints a one-line summary (lines, bytes, hardpoint count, seconds).
- `build-all <folder> [-o OUT_DIR] [--jobs 8] [same flags]` → every `*.glb` in the folder (non-recursive), one process per ship, a result table, non-zero exit if any failed (others still complete).
- `inspect <bundle>` → header JSON + line count.
Steps: parse GLB (JSON + BIN, accessors with byteStride, node TRS/matrix) → world-space triangles per mesh node → per mesh: weld (round to 1 mm), feature edges (boundary, or dihedral > crease) → transform → visibility cull (unless `--no-visibility`) → size-relative min length (relative to the ROBUST extent — see below) → **stray-fragment filter** (drop edges whose midpoint is farther than 1.25× the robust radius — 99.5th percentile distance from the median centre) → budget (longest first) → quantise. **Robust extent:** the reference size for the min-length threshold AND the visibility depth-map pixel is computed once, right after edge extraction, from the same rule as the stray filter (bounds of edges within 1.25× the 99.5th-percentile distance from the median midpoint) — a stray fragment (e.g. a decal 25 m off the Ironclad's nose) must not inflate the ship's size and thin the wireframe; the build prints a warning when that robust box is more than 10% smaller than the raw one. Class name: `--class-name`, else `extras.entity_name` of the first node carrying it (strip `EntityClassDefinition.`), else error. The edge step must be vectorised (no per-edge Python loops); target < 60 s for a 120 MB / 3.9M-triangle GLB on one core.
**Bundle format** (`.swf.gz`): gzip of `b"SWF1"` + `uint32 LE headerLen` + header JSON (UTF-8) + `int16 LE` array of `lines × 6` values. Header: `{format: 1, kind, className, sourceName, space: "gltf-y-up-m", center: [x,y,z], halfExtent: h, lines: n, nodes: [{name, parent: idx|-1, pos: [x,y,z]}], build: {creaseDeg, minEdgeFrac, maxLines, visibility, depthRes, tool: "wireframes/<ver>"}}`. Position = `center + int16/32767 × halfExtent`. `nodes` lists every NAMED node (world position, metres) whose name starts with `hardpoint` (case-insensitive) or that has such a descendant or ancestor — enough for the server to walk slot paths; capped at 5,000 nodes.

## 2. Server — hangar-service
- **Storage:** bundle bytes in a private GCS bucket `HANGAR_MODELS_BUCKET` (production `revenant-discord-bot-2-hangar-models`, uniform access, no public access; `hangar-runtime@` gets `roles/storage.objectAdmin` on it) at `models/<kind>/<className>.swf.gz`; metadata in Firestore `models/{kind}:{className}` = `{kind, className, vehicleUuid|null, vehicleName|null, lines, bytes, sha256, header.build, slots: {matched: n, missing: [...], ambiguous: [...]}, uploadedBy, uploadedAt}`. A `ModelStore` interface with GCS+Firestore and in-memory implementations (tests). Unset bucket → model routes answer 503 `unavailable`, everything else unaffected.
- **Admin routes** (session principal in `HANGAR_ADMIN_IDS`, same-origin; under `/api/v1` only): `POST /api/v1/models` (raw body `application/octet-stream`, ≤ 2 MB; validates gzip → magic → header schema → `lines×12` bytes present, `kind == "vehicle"`, ≤ 80,000 lines, decompressed ≤ 8 MB) → resolves `className` to a catalog vehicle (`vehicle_by_class_name`; unknown → stored with `vehicleUuid: null` and reported, still listable/deletable), matches slots, writes positions, returns the metadata; re-upload replaces. `GET /api/v1/models` → list. `DELETE /api/v1/models/{kind}/{className}` → deletes bundle + metadata + the positions doc if its `source == "extracted"`.
- **Slot matching:** for each catalog slot id (`a/b/c`): nodes named `a` (case-insensitive) → for each further segment the nearest descendants with that name (BFS, not descending past a match). Exactly one → `vehiclePositions/{vehicleUuid}.slots[slotId] = {xyz: [x,y,z]}`; none → `missing`; several → if all within 0.05 m of each other use the first, else `ambiguous` (no position). The doc is REPLACED with `{slots, space: "gltf-y-up-m", source: "extracted", className, updatedAt, updatedBy}` (hand-placed 2D points are not preserved — none exist).
- **Member routes:** `GET /api/v1/models/vehicle/{uuid}/wireframe` (any authenticated principal) → the stored bytes with `Content-Type: application/octet-stream`, `Content-Encoding` NOT set (the client gunzips), `ETag: "<sha256>"`, `Cache-Control: private, max-age=86400`, 304 on `If-None-Match`; 404 `not_found` when absent. `/catalog/vehicles/{uuid}/slots` → `vehicle.hasWireframe: bool` (false when the store is unavailable).
- Logs: INFO `hangar: model upload kind=… class=… vehicle=… lines=… bytes=… matched=… missing=… ambiguous=… by=<id>` and `hangar: model delete …`.

## 3. Editor
- `three` added as a dependency, imported ONLY inside the lazily loaded viewer chunk.
- `components/wireframe/WireframeViewer.tsx`: props `{bundle: ArrayBuffer, markers: {id, label, xyz}[], selected: id|null, onSelect(id)}`; decodes the bundle (`lib/swf.ts`: gunzip via `DecompressionStream`, parse header, dequantise), draws `LineSegments` (additive cyan, opacity ~0.32), OrbitControls (rotate/zoom/pan, damping), gentle auto-rotate until first interaction, markers as small spheres (selected: white, larger, pulsing unless reduced motion), hover tooltip with the slot label, click → `onSelect`; selecting a port eases the orbit target toward it. Disposes GL resources on unmount. `prefers-reduced-motion` disables auto-rotate and pulsing.
- `ShipPanel`: when `vehicle.hasWireframe`, fetch the bundle (TanStack Query, `staleTime` 1 day) and positions; show the viewer by default with a `Wireframe | Render` switch; stats overlay and ship name stay. WebGL unavailable, bundle fetch/decode failure or chunk-load failure → render panel with a short note. Markers = slots with `xyz` in positions; labels from `slotLabel`.
- **Admin "Ship models" page** (`/admin/models`, nav link only for admins; non-admins get the not-found page): multi-file drop zone / picker (`.swf.gz`), upload of up to 3 in flight, paced at least 2 s between starts (the server's Wiki lookups share a 60/min limiter with hangar reads), with per-file result (ship matched, lines, size, slots matched / missing / ambiguous lists), table of stored models (ship, class name, lines, size, matched/missing counts, uploaded at/by) with Preview (same viewer in a dialog) and Delete (confirm).

## Error handling
Upload validation errors → 400 `invalid_request` naming the problem; over limits → 413; storage errors → 503 `unavailable` with nothing half-written (metadata written after the object; on metadata failure the object is deleted). The viewer never blocks editing: every failure falls back to the render panel.

## Testing
- **tools/wireframes (pytest, synthetic GLBs built in tests):** GLB parse incl. node transforms and byteStride; feature edges on a cube (12 edges) and a subdivided cube (still 12 at 60°); welding of split vertices; visibility cull on a closed box containing an inner box (inner edges removed) and a box with a window (inner edges seen through it kept); min-length and budget (longest kept); stray-fragment filter; class-name extraction and override; bundle round-trip (write → read → positions within quantisation error); `build-all --jobs` honours the job count and continues past a failing file; thread env vars set.
- **hangar-service:** bundle validation (bad gzip/magic/header/length/too big); admin-only + same-origin; upload → metadata + object + positions; slot matching (nested, case-insensitive, missing, ambiguous, coincident duplicates); unknown class name; replace; delete (incl. positions cleanup rule); wireframe serve (200/ETag/304/404, any member); `hasWireframe`; bucket unset → 503 on model routes only.
- **Editor (Vitest):** `lib/swf` decode against a bundle fixture built in the test; marker selection logic; switch persistence + default; fallbacks (no WebGL, fetch error); admin page upload flow/results/table/delete; admin gating. three.js rendering itself is not unit-tested (mock the viewer module).
